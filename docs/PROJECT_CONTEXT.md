# Icon Lab — 项目上下文与云端接续

## 当前状态
这是个人图标设计工具原型，使用 HTML / CSS / JavaScript，无前端编译步骤。
当前入口是根目录 index.html；主要逻辑 app.js；样式 style.css；基础图标 library.js。
演示素材 samples/ 和运行依赖 vendor/ 已包含在仓库中。
GitHub Pages 从 main 分支根目录发布。

## 运行与检查
- 在仓库根目录启动静态 HTTP 服务。若环境提供 Python，可运行：
  python3 -m http.server 4173 --bind 0.0.0.0
- 使用云端环境提供的预览方式打开该服务；另一台电脑的 localhost 不指向云端机器。
- 本地个人开发时可绑定 127.0.0.1。
- 不要直接双击 HTML；代码使用 ES modules。
- 无需为现有原型执行 npm install 或 npm build。
- 验证页面、图标库、状态动效与导出时，保留现有浏览器数据。

## 已有能力
- 参考 SVG 上传、显式规范参数调整、预览。
- 50 个基础图标及搜索。
- Morphicons 线性路径变形。
- SVG / PNG 状态转场。
- 静态与动效资产本地保存及恢复编辑。
- SVG、PNG、GIF、动画 SVG、Lottie 导出实现。
- JSON 项目备份导出。

## 当前边界
- AI 候选为预置演示，没有实时 AI API。
- 资产存储为浏览器 localStorage（iconflow-v1），不是团队共享数据库。
- 同步 Codex 聊天或 GitHub 代码不会同步浏览器里保存的图标、动效资产。
- 备份恢复导入入口、团队身份与权限、版本审核、Figma 插件均未实现。
- transform 等部分 SVG 结构被现有导入器拒绝。
- WebP 编码未接入；完整导出兼容性仍需验证。

## 后续产品方向（规划建议，未实现）
以团队图标的发现、提交和复用为核心。
首先验证“设计师 A 提交 → 设计师 B 找到 → 实际复用”。
Figma 集成优先使用插件，入口为“搜索并复用”和“提交 / 更新”；MCP 为后续可选 AI 接口。
区分资产、平台/状态变体、历史版本和交付记录。
避免重复同步制造新资产；把小规模真实任务验证提前。
AI、复杂动效、外部平台同步按证据分阶段投入。

## 跨设备接续
- 在同一账号和工作区内，从支持的客户端继续同一 Codex Cloud 任务。
- GitHub 提交保存可复用代码版本；云端任务自身保存当前任务的工作状态。
- 旧本地聊天不会因本文件而自动变成云端聊天；本文件提供起始上下文。
- 结束工作时，记录改动文件、验证情况、未完成事项和下一步；更新 docs/DEV_LOG.md。
- 多个任务各有工作状态；接续前核对分支和最新提交，避免覆盖其他任务修改。

## 首次云端任务提示词
请阅读 docs/PROJECT_CONTEXT.md，检查仓库源码，先概述现有功能、限制与下一步。先启动静态预览并验证图标库和状态动效，不改产品功能。后续按用户指定的范围开发，并把重要进度写入 docs/DEV_LOG.md。
