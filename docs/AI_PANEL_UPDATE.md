# AI 生成面板与成员配置

2026-11-08。

- 面板保留规范读取与确认、需求描述、生成候选三组主要操作。连接设置、发送内容、试用示例和生成记录按需展开。去掉重复流程标语与旧的 24×24 提示。
- 需求改为最多 2000 字符的多行文本，可说明图形内容、场景、含义和细节约束。Enter 换行，⌘ / Ctrl + Enter 生成。导航和刷新保留需求草稿，保存候选记录完整需求。
- 已获准使用 AI 的成员可在连接设置中填个人 Qoder PAT、Agent ID、运行环境 ID、模型和预算。保存前只用 GET 检查资源权限和 Agent 约束，不创建生成会话。该检查不能保证未来额度充足或生成一定成功。
- PAT 与配置使用 Supabase Vault 加密保存，由服务端验证登录后按成员读取。页面只获得配置状态与非密钥字段；密钥不回显、不写入浏览器存储。空 PAT 表示保留已存密钥。可以移除个人配置并使用团队接口。
- 个人配置存在时优先使用；失效、存储故障或凭据服务不可用时明确报错，不静默切换到团队额度。保留现有来源白名单、账号白名单和请求限流。
- 数据库私有表开启 RLS、显式拒绝客户端访问。公开 RPC 为 invoker，仅 service_role 能执行；Vault 访问限定在私有服务函数。删除配置及用户级联删除都会清除对应 Vault 记录。

验证：完整自动检查 341 项通过；数据库真实事务内验证了加密往返、替换、不同成员无配置、删除及密钥清理，并回滚测试数据。普通账号和匿名角色无法执行密钥 RPC。个人 PAT 的真实生成需由成员在页面填写后验证；当前未读取或使用任何成员个人 PAT。

Figma 部分仅分析，见 FIGMA_AI_PLAN.md。个人配置的跨设备存储由服务端实现，尚未进行两台真实设备的往返验收。

技术依据：[Supabase Vault](https://supabase.com/docs/guides/database/vault)、[Qoder Agent 查询](https://docs.qoder.com/cloud-agents/api/agents/get)、[Qoder 环境查询](https://docs.qoder.com/cloud-agents/api/environments/get)。
