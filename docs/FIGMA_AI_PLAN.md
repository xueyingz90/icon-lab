# Figma 内生成图标：可行性与下一步方案

2026-11-08。本轮为源码与官方 API 分析，尚未实现，也未在 Figma 客户端验收。

可行。现有插件已监听选区变化，读取单个 Frame / Component / Instance 的尺寸、名称及 SVG，并支持将 SVG 插入为 Figma 图层。下一步可复用网页的登录、个人 Qoder 配置、规范确认和三候选生成服务，省去手动导出、上传 SVG。

建议流程：选中图标画板 → 读取原生参数与预览 → 确认规范 → 描述图形与场景 → 生成三个候选 → 插入所选候选。

## 首版范围（P0）

- 先支持一个图标画板；明确排除完整产品页面、含大量文本的复杂画板。一个样本可以开始，但不足以代表整套设计系统。
- 直接读取画板宽高及可见子节点的描边、端点、连接、填色等。参数混用时展示分布或“待确认”，不取一个平均数冒充规范。
- SVG 与 PNG 预览补充形状上下文；视觉重心、几何语言等作为 AI 推断呈现，需人工确认。SVG 导出可能转换复杂笔画，不能仅凭导出的 SVG 判断原始描边属性。
- 使用已登录成员的云端配置，个人 PAT 仍留在服务端，不写入插件存储。
- 授权发送参考后才请求 AI；选区或图层内容变化，使规范确认失效。生成期间的变化应丢弃过期结果。
- 插件展示三个候选，仅将用户选择的结果插入画布。建立独立结果画板，保留宽高与可编辑矢量；不覆盖原图。
- 记录需求、规范、来源节点、模型和生成时间。插入和保存到团队资产库分为两个明确操作。

## 后续（P1）

支持选择 3–8 个图标，或一个只包含图标子画板的参考集合。先列出检测到的图标，允许排除背景、文本、隐藏和异常尺寸节点，再分析整组共性。整张业务界面自动推断全套规范，应放到后续研究阶段。

## 验收边界

首版需在真实 Figma 客户端验证：32×32 与 48×32 选区；混合描边提示；选区变化丢弃结果；个人与团队连接；三个候选插入；撤销；可编辑性；原图保留；未授权不发送素材；失败不产生空图层。当前这些仅为待实现的验收要求。

## 依据

源码：figma-plugin/code.js 中 capture / verify / insertSVG 已具备选区导出、复核和插入桥接。插件 v0.4.4 的实际入口仍为同步与资源库，没有 AI 生成页。

官方文档：[节点 exportAsync](https://developers.figma.com/docs/plugins/api/properties/nodes-exportasync/)、[SVG 导出设置](https://developers.figma.com/docs/plugins/api/ExportSettings/)、[createNodeFromSvg](https://developers.figma.com/docs/plugins/api/figma/#createnodefromsvg)。以上为可行性判断依据，不代表新增流程已实现。
