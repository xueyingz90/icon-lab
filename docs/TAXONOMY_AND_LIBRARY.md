# 多维分类与 Figma 资源库（v0.6.0 / 插件 v0.4.0）

本次为现有项目增量更新。Figma 上传链路已由用户确认跑通，本次保留其选区读取、导出、确认、登录、重复处理、版本和权限流程，只增加四个可选元数据与独立的查询/插入功能。不使用 MCP，无新增运行框架。

## 使用

网页“资产库”优先显示图形结构、视觉风格筛选；展开“更多筛选”选择颜色模式和适用平台。各维度与名称搜索取交集；“重置筛选”清空所有条件，并恢复“全部”资产范围。每个维度可选择“未分类”。上传和更新版本的表单可分别设置四个维度，允许 Filled + Glassmorphism + Multicolor + App 同时存在。

插件登录同一工作台账号并选择同一空间后，点击“资源库”。支持名称搜索、结构/风格组合筛选、缩略图、重置及每页 24 项的“加载更多”。点击“插入画布”，图标出现在当前页面视口中心，自动选中。只读成员也能调用已有图标；上传仍需编辑权限。调用不创建资产或历史版本。

## 数据兼容

在原 `il_assets` 表增加可空字段，不新建图标库：

| 字段 | 值 |
| --- | --- |
| structure | Outline / Filled / Hybrid |
| visual_style | Flat / Gradient / Glassmorphism / Volumetric |
| color_mode | Monochrome / Duotone / Multicolor |
| target_platform | App / Glasses / Other |

每个维度各存一个可选值，四个维度独立。`target_platform` 与旧 `platform` 分开，以保留原设备规范和去重规则使用的旧字段。空值是“未分类”，不是自动猜测的默认分类。

迁移保留原 platform、visual_type、ID、SVG、时间、版本与历史记录。明确的线性→Outline、面型→Filled；单色/双色/多色只映射颜色模式；App/AI 眼镜/其他设备只映射平台。旧“彩色”不能判断双色或多色，保持未分类；旧“通用”也不推断成 Other。旧分类无法推导视觉风格，因此该维度全部保留空值。旧历史不回填。

旧 `il_save_asset` 的参数、授权、版本控制及公开 API 保持不变。新字段走原有 `p_meta`；旧插件省略这些字段时保留已有分类。首次重复同步不会因为新增字段凭空增加版本。新客户端显式提交 null 可清除分类。普通网页元数据编辑保留未更改的旧原始分类文字。

网页和插件共用 `CloudClient` 和同一个 `il_assets` REST API、用户令牌、空间及 RLS。插件查询有服务端筛选和分页；网页仍保留现有最多 500 项加载范围，组合筛选作用于已加载记录。大规模全库网页分页不在本次范围。

## 插入边界

先复用原 SVG 安全校验，再由主线程调用 [figma.createNodeFromSvg()](https://developers.figma.com/docs/plugins/api/figma/)，保留 API 支持的矢量结构，不栅格化。选中新节点并调用 [scrollAndZoomIntoView](https://developers.figma.com/docs/plugins/api/figma-viewport/)。实际 SVG 效果受 Figma 支持范围限制；渐变、裁剪、文字轮廓等复杂内容需要实机检查。

PNG 等非 SVG 资源显示明确提示并禁用“插入画布”。本次没有新增图片插入。继续使用现有安全 SVG 范围，不支持外部图片、脚本、CSS 样式表或滤镜。原始不支持的内容会报错，不会冒充可编辑矢量。

插件缓存仅在本次运行内保留，账号/空间变化即清空并丢弃过期查询结果；会话失效会恢复登录表单。插入不会自动上传。超时会提示先检查画布，避免重复插入。

## 部署顺序（已有项目）

1. 先在现有 Supabase 项目的 SQL Editor 执行**仅本次** `supabase/migrations/20261031125455_asset_taxonomy.sql`，它有事务保护。不要重跑 `backend/001_asset_library.sql`，不要删除旧表或清空数据。标准表与本次分类迁移相互独立。
2. 再将本版本源码发布到 xueyingz90/icon-lab 的 main 根目录，保留已有 .git 和其他未涉及文件。GitHub Pages 仍用 main / (root)。不需要重新填写 Key 或创建第二个后端。
3. 等待 Pages 构建成功，打开 `https://xueyingz90.github.io/icon-lab/?v=20261031-taxonomy-8`；若旧标签页仍打开，重新加载。
4. 关闭正在运行的 Figma 插件，解压 v0.4.0 包，覆盖原安装目录的 code.js 与 ui.html。保留 Figma 分配的 manifest ID；本版 ID 与旧开发包一致。再次运行，确认底部 v0.4.0。
5. 登录相同账号、空间，先查旧图标，再上传一个个人测试 SVG，设置四维分类，网页组合检索后，在插件中查到同一资产并插入。

1. 原上传预览和确认正常，网页可查到新上传记录。
2. 新图标可同时设置 Filled、Glassmorphism、Multicolor、App；旧图标可查看/下载，未知分类显示未分类。
